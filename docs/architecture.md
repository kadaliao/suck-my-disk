# Architecture

**English** · [简体中文](architecture.zh-CN.md)

How SuckMyDisk turns a disk into a list of things you can safely remove. Read
this before changing the scanner, the live index, a recognizer or the
executor.

## Layout

```
App/                          SwiftUI app (macOS 26, Liquid Glass)
  SuckMyDiskApp.swift         window, menu bar item, Settings, ⌘R
  AppModel.swift              state: index, live loop, report, selection, cleanup
  Updater.swift               self-update schedule: when to check, download, install, relaunch
  Snapshotter.swift           --snapshot mode: renders every section to PNG
  Demo.swift                  --demo mode: made-up data for screenshots and trying the app
  Views/                      Overview, Category (reclaim lists), Treemap, Timeline, Clean Up page, shared components
  AppIcon.icon/               Icon Composer icon (generated by scripts/make-icon.py)
Packages/DiskCore/            Swift package: the engine and the smd CLI
  Sources/CFastScan/          parallel getattrlistbulk walker, compact tree, snapshot file, live patch API (C)
  Sources/DiskIndex/          ScanTree, live updates, shared-data accounting, privacy, guards, SQLite store
  Sources/Insights/           activity signals (Claude Code, Codex, shell history, Spotlight)
  Sources/Recognizers/        projects, frames, dev caches, models, installed apps, app data, system; report and planner
  Sources/Reclaim/            executor: re-checks guards, acts, writes the journal
  Sources/Update/             self-update: GitHub release, checksum and signature checks, swap, relaunch
  Sources/smd/                command line
  Tests/DiskCoreTests/        Swift Testing suites
scripts/                      release, icon and screenshot tooling
project.yml                   XcodeGen spec for the app (the .xcodeproj is generated, not committed)
```

Module dependencies (from `Package.swift`):

```
CFastScan ← DiskIndex ← Insights ← Recognizers ← Reclaim
                ↑                                   ↑
                Update (app only)    smd and the app use all of them
```

## The data flow

```
            ┌──────────── first run / rescan ────────────┐
disk ──► CFastScan.scan ──► ScanTree ──► index-<uuid>.bin │
            └────────────────────────────────────────────┘
FSEvents ──► DiskWatcher ──► LiveIndex.patch ──► ScanTree (kept current)
                                                     │
ActivityIndex ───────────────────────────────────────┤
                                                     ▼
                                   Recognize.all ──► Report (Things → ReclaimItems)
                                                     │        └─► last-report.json, history
                                   Planner.plan  ◄───┘  (selection or preselection)
                                         │
                                   Executor.run ──► Guards ──► delete / trash / tool command
                                                     └─► journal (smd.sqlite)
```

## Scanning (`CFastScan`)

The scanner is C for speed. Worker threads walk directories with
`getattrlistbulk`, which returns names, sizes, dates, inode and clone
information for many entries per system call.

- **The tree** is one flat array of `sm_node`. Node 0 is a synthetic root
  whose children are the scan roots; children always have larger indices than
  their parents. Each node holds its own values (allocated bytes, shared
  bytes, logical size, newest mtime, image / video / audio / model bytes,
  marker bits) and subtree totals (`t_alloc`, `t_shared`, `t_newest`, …)
  filled in after the walk.
- **Small files are not nodes.** Files below the big-file threshold (1 MiB)
  are added to their directory's own totals; only big files get a node. This
  keeps a five-million-file disk to a manageable node count.
- **Folding.** Well-known dependency and cache folders (`node_modules`,
  `.git`, `.venv`, `__pycache__`, `.next`, `.build`, `Pods`, `_cacache`, …)
  are walked but stored as one node with `SM_F_COLLAPSED`. The children of
  `DerivedData` are folded the same way. Bundles (`.app`, `.framework`,
  `.photoslibrary`, …) are leaves with `SM_F_PACKAGE`.
- **Markers.** While reading a directory, well-known names set bits on it:
  `.git`, `package.json`, `pyproject.toml`, lockfiles, `pyvenv.cfg`,
  `CACHEDIR.TAG`, video files and so on. Recognizers work from these bits
  instead of reading directories again.
- **Not entered:** other volumes (`SM_F_MOUNTPOINT`), iCloud placeholders
  (`SM_F_DATALESS`), unreadable folders (`SM_F_DENIED`) and the folders in
  the skip list (see [Privacy](#privacy)).
- **The data volume.** The scan root is `/System/Volumes/Data`. `Firmlinks`
  maps between data-volume paths and the paths users see (`/Users/…`) using
  `/usr/share/firmlinks`.

A full scan of about 5.2 million files takes around 36 seconds and is bound by
APFS in the kernel: more threads, `openat`, or asking for fewer attributes
did not make it faster. `smd bench` measures scanner speed by thread count.

### Clones and hard links

APFS clones and hard links share data blocks. The scanner marks such files
`SM_F_SHARED` and splits their allocated size evenly across the members, so
totals add up and nothing is counted twice (`ScanTree.uniqueTotal`,
`stats.shared_unique`).

An even split is right for totals, but not for "what does deleting this
free". `SharedAccounting` answers that question for a set of roots: it
rescans them collecting every clone / hard-link member, groups members by
clone id or inode, and reports, for any subset of roots, the bytes that come
back (own data plus groups whose members are *all* deleted) and the bytes that
stay trapped because something outside still references them. The uv
recognizer uses it for the cache plus `.venv`s, and `Recognize.refineShared`
uses it to replace lower-bound estimates for large shared items.

### The index file

`ScanTree.save` writes the tree to
`~/Library/Application Support/SuckMyDisk/index-<volume-uuid>.bin`. The file
starts with a magic string (`SNAP_MAGIC` in `fastscan.c`, currently
`SMDIDX03`) and the node size. **Change `SNAP_MAGIC` whenever the node layout
or file format changes**: older files are then rejected and the next launch
does one full scan instead of misreading them. Mention it in the changelog.

## Live updates (`LiveIndex`)

- `DiskWatcher` subscribes to FSEvents for the data volume, starting from the
  event id stored in the index, so events that happened while the app was
  closed are replayed first. FSEvents reports directories, not files.
- `LiveIndex` turns a batch of changed directories into work: re-read a
  directory's own entries, scan a new subtree, detach a removed one
  (`SM_F_DETACHED`). The C patch API edits the tree in place and fixes the
  totals up the parent chain.
- Folders that change constantly are re-read at most every few seconds. Big
  folded subtrees and folders with more than 20,000 files, or that are slow to
  read, are deferred: marked `SM_F_STALE` and refreshed in the background
  every few minutes. Stale marks are saved in the index.
- When events were dropped, event ids wrapped, or the FSEvents database UUID
  no longer matches the one in the index, the batch asks for a full rescan
  (`rescanAll`), which is the only correct answer then.
- `LiveIndex.stamp` records the event id from *before* a full scan started, so
  changes made during the scan are replayed rather than lost.

Catching up after the app was closed for a while takes about 0.3–1 seconds;
following the disk costs about 1% of one core. The app reruns recognition in
the background when enough has changed; `smd` catches up on every run.

## External disks

`ExternalVolumes.list()` finds local, writable, browsable volumes under
`/Volumes` from volume attributes alone: no folder is read, so listing never
raises a privacy prompt. Network shares, read-only disk images and hidden
volumes (Time Machine) are left out.

Each disk is scanned with the same scanner, its mount point as the only root,
into its own `index-<volume-uuid>.bin`. `Recognize.external` runs only the
project and frame recognizers, with `allowAnyPath` set (projects anywhere, not
just in the home folder) and the disk's top-level dot folders off limits
(`.Trashes`, `.Spotlight-V100`, and dot folders moved off the home folder,
which are full of `package.json` + `node_modules`). Its report goes to
`report-<volume-uuid>.json`.

External disks have no FSEvents stream: the app scans one when it mounts
(`NSWorkspace.didMountNotification`) or is present at launch, on Rescan, and
after Clean Up, and shows the saved index and report meanwhile. Without Full
Disk Access it scans only when the user asks, because macOS prompts before an
app reads an external disk. `smd things /Volumes/<name>` and
`smd reclaim /Volumes/<name>` do the same from the command line.

`Executor` measures freed space on the volume that holds the item
(`ExternalVolumes.mountPoint`), and `Guards.isDenied` refuses any volume's root
folder.

## Privacy

Without Full Disk Access, reading Desktop, Documents, Downloads, iCloud Drive,
`~/Library/Containers`, `~/Library/Group Containers` or `/Volumes` raises a
consent dialog. `Privacy.rootsToSkip()` returns those folders when the process
lacks Full Disk Access (checked by trying to open the TCC database, which never
prompts), and the scanner, the live updater and the recognizers all leave them
alone. `LiveIndexTests.privacyPromptingFoldersAreNeverOpened` guards this.
`--snapshot` and `--demo` runs set `Privacy.alwaysSkip` so they never touch
them.

## Recognition (`Recognizers`, `Insights`)

`Recognize.all` builds a `Report` from the tree:

1. `ActivityIndex` loads "when did I last work here" signals: Claude Code and
   pi session folders, Codex session working directories, `cd` lines in fish
   and zsh history, and Spotlight last-used dates.
2. `ProjectRecognizer` walks the tree once, finds projects (git or a manifest)
   and their artifacts, runs `git check-ignore` / `git ls-files` in parallel
   only for generic folders (`build`, `dist`, `out`) big enough to list, and
   decides which items are preselected.
3. `FrameSequenceRecognizer` finds folders with many images, reads a few image
   headers, and looks for a nearby video with the same number of frames (its
   video track's duration × frame rate, within 3 frames or 0.5%). Going up
   from the frames, it passes over other projects (folders with a git repo or
   manifest) and folders holding other frame sequences, and prefers the newest
   video on a tie.
4. `DevCacheRecognizer`, `ModelRecognizer`, `AppDataRecognizer` and
   `SystemRecognizer` handle the rest.
5. `AppRecognizer` lists the apps in `/Applications` and `~/Applications` (and
   one folder down) from their `Info.plist`, and matches their folders in
   `~/Library` by bundle id, by names that extend it (`….ShipIt`, an
   extension's id; the longest installed id wins), and in Application
   Support, Caches and Logs by the app's exact name unless it is generic or
   shared. Folders come from the tree, so privacy-protected ones are never
   read; small files (preferences, cookies, launch agents) from a directory
   listing. Each app becomes a `.app` Thing with an Uninstall item (`yours`, a
   `compound` of `.trash` actions, the bundle first) and, when they add up to
   1 MB, a Caches item (`regenerable`, `.deleteAll`), both carrying `app`.
   Apps go last in the report so `smd things` numbers for everything else
   stay put.
6. `refineShared` measures large items whose estimate is only a lower bound.

The model, in `Thing.swift`:

- A **`Thing`** is something a person recognizes: a project, a cache, a model
  store. It has a kind, a size, last activity and a list of items.
- A **`ReclaimItem`** is one action: what it frees (`estimate`, which can be
  less than `bytes` it occupies), its `Tier`, its `ReclaimAction`, a restore
  command, a reason, warnings, and whether it is preselected. `covers` lists
  items it already includes (`uv cache clean` covers `uv cache prune`) so
  they are not counted or run twice. `app` is the bundle path of the
  installed app an item belongs to.
- **`Tier`**: `lossless` (nothing is lost; reserved for clone merging),
  `regenerable` (deleted, can be rebuilt), `yours` (to the Trash), `guide`
  (instructions only).
- **`ReclaimAction`**: `delete`, `deleteAll`, `trash`, `command` (a tool's own
  cleanup), `compound`, `none`.

`Planner.plan` turns a selection (or the preselection) into the list of items
to run, dropping covered ones.

Every recognizer must follow the rules in
[CONTRIBUTING.md](../CONTRIBUTING.md#safety-rules-for-code-that-deletes).

## Execution (`Reclaim`)

`Executor` runs items one by one. Right before each, for every path the action
touches, it checks `Guards.isDenied`, that the path exists and is not a
symlink, that git tracks nothing in it (failing closed), that no running
program's command line names it (`ps`, also failing closed), and the 7-day
rule. `force` lifts that rule for every item; `chosen`, the items the person
ticked by hand, lifts it for the regenerable ones among them, so preselected
items that changed after the scan stay put. For uv's commands it also checks
that no uv is running, since uv would wait on its cache lock, and sets
`UV_LOCK_TIMEOUT` in case one starts meanwhile. It also refuses anything System
Integrity Protection guards (`SF_RESTRICTED`).

Items with an `app` get more: the app must still be installed, and nothing may
run from it (`Guards.program(inApp:in:)`, which also catches a translocated copy
by its `/<Name>.app/Contents/` path). Picked by hand, they skip the 7-day rule,
because opening an app changes its folders and "not running" is the check that
matters. Folders that vanished since recognition are dropped from the action
rather than failing it (`Executor.existing`).

Then it acts: `removefile` for deletes,
`FileManager.trashItem` for the Trash, or the tool's command through `Shell`.
An `.app` bundle that `trashItem` can't move (it belongs to root, as App Store
and installer apps do) is handed to Finder through `osascript`, which asks for
an administrator password like a drag to the Trash would.
Before deleting a Python virtualenv it records `pyvenv.cfg` and a
`pip freeze`. Free space is measured before and after, and everything goes
into the journal.

## Storage

`AppPaths.supportDir` is `~/Library/Application Support/SuckMyDisk`, or
`$SMD_HOME` when set.

| File | Written by | Contents |
| --- | --- | --- |
| `index-<volume-uuid>.bin` | `ScanTree.save` | the tree, with the FSEvents id and database UUID it is current to |
| `last-report.json` | `ReportStore.save` | the latest `Report`; removed after a cleanup |
| `report-<volume-uuid>.json` | `ReportStore.save(_:to:)` | an external disk's latest `Report` |
| `smd.sqlite` | `Store` | `history` (bytes per thing per day), `volume_history`, `journal` |

## The app

`AppModel` owns the state: the loaded tree, the live loop, the report, the
selection (kept across refreshes, and shared by every disk), the plan and
cleanup progress. Each external disk is an `ExternalDisk` with its own tree,
report and scan phase; `page` says whether a startup-disk section or a disk is
on screen, and `cleanDisk` which disk Clean Up works on. It starts
from `AppDelegate.applicationDidFinishLaunching`, so it works even when the
app opens with only the menu bar item, and saves the index on quit.

`--snapshot <dir>` renders every section to PNG and quits;
`scripts/snapshots.sh` launches the app that way through LaunchServices
(Liquid Glass only renders properly then) and captures the window from a
terminal that has Screen Recording permission.

Reclaim lists are `CategoryView`s, one per section (`.id(section)`, so each
opens its own first groups). Apps differ in a few places: the sidebar, card and
header show the space apps take up rather than "reclaimable" (uninstalling
every app is not a plan), the overview's "awaits your call" leaves them out,
the timeline and capacity bar leave them out (they overlap App data and
Applications), each row shows the app's icon, and an Uninstall item lists its
data folders with sizes from the tree (`AppDataList`). The Clean Up sheet groups
uninstalls on their own.

`--demo` replaces the disk with made-up data from `Demo.swift`: a report, an
index built by `ScanTree.synthetic` from a list of folder sizes (an empty
tree from `sm_tree_create`, filled in through the live-update patch API, with
no disk access), two weeks of timeline, volume numbers, made-up apps (with
initial-letter tiles for icons, so no real app's icon shows), and a made-up
external disk ("Studio SSD"). `AppModel` then
skips rescans and saving, and Clean Up only removes the items from the lists;
demo items never reach the executor. `scripts/doc-screenshots.sh` runs
`snapshots.sh` in demo mode for the screenshots in `docs/images`.

## Updates (`Update`, `Updater`)

`Updates.latest` reads `releases/latest` from the GitHub API, which skips
drafts and pre-releases, and accepts the release only when its tag is a plain
version (`v0.5.1`) and its assets include `SuckMyDisk-<version>.zip` and
`SHA256SUMS`. `release.sh` makes exactly those, so publishing a release is all
it takes. Installing one:

1. `download` fetches `SHA256SUMS`, then the zip into
   `~/Library/Caches/com.kadaliao.SuckMyDisk/Updates` (a good copy already
   there is reused), and drops the zip unless its hash matches.
2. `unpack` expands it with `ditto` into an `itemReplacementDirectory` on the
   installed app's volume, and `verify` checks the app:
   `SecStaticCodeCheckValidity` (all architectures, nested code, strict)
   against `Updates.requirement` (bundle id, Developer ID Application, team
   `HMDAVG9B8J`, `notarized`), then its `Info.plist` version must equal the
   release's. Only versions newer than the running one are taken, so an old
   genuine release can't be replayed.
3. `swap` trades the two bundles with `renamex_np(…, RENAME_SWAP)`, so a whole
   app is at the path at every moment, and deletes the old one.
4. `relaunch` posix_spawns `/bin/sh` in a new session (launchd would kill it
   with the app's job otherwise) that waits for the app's PID to exit and runs
   `open -a`. `--hidden` keeps the window closed
   (`defaultLaunchBehavior(.suppressed)`) when it was closed before.

The designated requirement doesn't change between releases, so TCC keeps the
Full Disk Access grant.

`Updater` in the app decides when. It checks 30 s after launch if the last
check is a day old, then ticks every minute. Network trouble is retried after
an hour; a version that fails its own checks or its install is left alone in
the background until a newer one comes out, and the sidebar card says why. A
downloaded update is checked at once, so a bad one is never left waiting. With
automatic install on, it installs when the app is inactive, not hidden, has no
window open, and nothing is loading, scanning, recognizing or cleaning, and
relaunches only if that still holds afterwards; otherwise
`applicationWillTerminate` installs it. A relaunch the user asks for waits for
a running scan or cleanup to end. `Updates.blocker`
explains when the app can't replace itself: App Translocation, a read-only
volume (the DMG), or no write access. Builds not signed with the Developer ID
(Xcode), `--demo` and `--snapshot` never check.

## Localization

All user-facing text, in the app and the CLI, goes through
`L("中文", "English")` in `Fmt.swift`. Chinese is used when the first
preferred language starts with `zh`; `SMD_LANG` overrides it. There are no
string catalogs: both languages live next to each other in the code, so a
change can't update one and forget the other.

Sizes use decimal units, like Finder (`Fmt.bytes`).

## Tests

`swift test` in `Packages/DiskCore` runs the Swift Testing suites against
fixtures built in temporary folders:

- `ScannerTests`: clone and hard-link counting, folding and markers, snapshot
  round trip, synthetic trees, firmlinks.
- `AccountingTests`: freeing a uv cache and a `.venv` together.
- `RecognizerTests`: project artifacts and restore commands, active projects
  not preselected, projects on an external disk (not in its dot folders),
  frames matching only their own video, npx packages, frame sequences versus
  camera bursts.
- `AppTests`: which apps are listed, which folders belong to which app
  (suffixes, team-id group containers, vendor folders and generic names left
  out), Homebrew and system-component warnings, running apps left alone
  (translocated copies too), hand-picked app items and the 7-day rule, a
  removed app reported, shared folders protected.
- `SafetyTests`: denied locations, covered items, executor refusing protected
  and git-tracked paths, files a running program uses, the 7-day rule and
  what lifts it, uv waiting for no one, Node scripts finding `node` from an
  app's bare PATH.
- `LiveIndexTests`: a patched tree equals a fresh scan, saved trees keep
  growing, big folders wait their turn, privacy-prompting folders are never
  opened, FSEvents drive the update.
