# 架构

[English](architecture.md) · **简体中文**

SuckMyDisk 怎样把一块磁盘变成一份「哪些可以放心删」的清单。改扫描器、实时索引、识别器或执行器之前，先读这篇。

## 目录结构

```
App/                          SwiftUI app (macOS 26, Liquid Glass)
  SuckMyDiskApp.swift         window, menu bar item, Settings, ⌘R
  AppModel.swift              state: index, live loop, report, selection, cleanup
  Updater.swift               self-update schedule: when to check, download, install, relaunch
  Helper.swift                turns the root helper on and off (SMAppService), shows its state
  Snapshotter.swift           --snapshot mode: renders every section to PNG
  Demo.swift                  --demo mode: made-up data for screenshots and trying the app
  Views/                      Overview, Category (reclaim lists), Treemap, Timeline, Clean Up page, shared components
  AppIcon.icon/               Icon Composer icon (generated by scripts/make-icon.py)
Packages/DiskCore/            Swift package: the engine and the smd CLI
  Sources/CFastScan/          parallel getattrlistbulk walker, compact tree, snapshot file, live patch API (C)
  Sources/DiskIndex/          ScanTree, live updates, shared-data accounting, privacy, guards, SQLite store
  Sources/Insights/           activity signals (Claude Code, Codex, shell history, Spotlight)
  Sources/Recognizers/        projects, frames, dev caches, models, installed apps, app data, system; report and planner
  Sources/Reclaim/            executor: re-checks guards, acts, writes the journal
  Sources/Update/             self-update: GitHub release, checksum and signature checks, swap, relaunch
  Sources/Privileged/         what the root helper does and how the app reaches it (no other module in it)
  Sources/smd/                command line
  Tests/DiskCoreTests/        Swift Testing suites
Helper/                       the root helper's program and launchd job (built into the app)
scripts/                      release, icon and screenshot tooling
project.yml                   XcodeGen spec for the app (the .xcodeproj is generated, not committed)
```

模块依赖（见 `Package.swift`）：

```
CFastScan ← DiskIndex ← Insights ← Recognizers ← Reclaim
                ↑                                   ↑
                Update (app only)    smd and the app use all of them

Privileged stands alone: the app and the helper use it, smd doesn't
```

## 数据流

```
            ┌──────────── first run / rescan ────────────┐
disk ──► CFastScan.scan ──► ScanTree ──► index-<uuid>.bin │
            └────────────────────────────────────────────┘
FSEvents ──► DiskWatcher ──► LiveIndex.patch ──► ScanTree (kept current)
                                                     │
ActivityIndex ───────────────────────────────────────┤
                                                     ▼
                                   Recognize.all ──► Report (Things → ReclaimItems)
                                                     │        └─► last-report.json, history
                                   Planner.plan  ◄───┘  (selection or preselection)
                                         │
                                   Executor.run ──► Guards ──► delete / trash / tool command
                                                     └─► journal (smd.sqlite)
```

## 扫描（`CFastScan`）

扫描器用 C 写，为了快。多个工作线程用 `getattrlistbulk` 遍历目录，一次系统调用就能拿到很多条目的名字、大小、日期、inode 和克隆信息。

- **树**是一个扁平的 `sm_node` 数组。0 号节点是虚拟的根，它的子节点是各个扫描起点；子节点的下标总是比父节点大。每个节点存自己的值（已分配字节、共享字节、逻辑大小、最新 mtime、图片 / 视频 / 音频 / 模型字节数、标记位），遍历结束后再填上整棵子树的合计（`t_alloc`、`t_shared`、`t_newest` 等）。
- **小文件不单独成节点。** 小于大文件阈值（1 MiB）的文件只计入所在目录自己的合计，只有大文件才有自己的节点。这样五百万个文件的磁盘，节点数也能控制住。
- **折叠。** 常见的依赖和缓存目录（`node_modules`、`.git`、`.venv`、`__pycache__`、`.next`、`.build`、`Pods`、`_cacache` 等）照样会遍历，但只存成一个带 `SM_F_COLLAPSED` 的节点。`DerivedData` 的子目录也这样折叠。包（`.app`、`.framework`、`.photoslibrary` 等）是带 `SM_F_PACKAGE` 的叶子节点。
- **标记位。** 读目录时，遇到常见的文件名就在这个目录上打一个标记位：`.git`、`package.json`、`pyproject.toml`、各种锁文件、`pyvenv.cfg`、`CACHEDIR.TAG`、视频文件等。识别器看这些标记位干活，不用再读一遍目录。
- **不进入的地方：** 其他卷（`SM_F_MOUNTPOINT`）、iCloud 占位文件（`SM_F_DATALESS`）、读不了的目录（`SM_F_DENIED`），以及跳过列表里的目录（见[隐私](#隐私)）。
- **数据卷。** 扫描从 `/System/Volumes/Data` 开始。`Firmlinks` 根据 `/usr/share/firmlinks`，在数据卷路径和用户看到的路径（`/Users/…`）之间互相转换。

扫一遍约 520 万个文件大概要 36 秒，瓶颈在内核里的 APFS：加线程、用 `openat`、少要几个属性，都没有更快。`smd bench` 可以按线程数测扫描速度。

### 克隆和硬链接

APFS 克隆和硬链接会共享数据块。扫描器把这类文件标成 `SM_F_SHARED`，并把已分配大小平均分给每个成员。这样合计能对上，也不会重复计算（`ScanTree.uniqueTotal`、`stats.shared_unique`）。

平均分摊算合计没问题，但回答不了「删掉这个能腾出多少」。这个问题由 `SharedAccounting` 来答：它把给定的几个根目录重新扫一遍，收集每个克隆 / 硬链接成员，按克隆 id 或 inode 分组，然后对任意一组根目录给出两个数：删掉后能拿回的字节（自己独占的数据，加上成员*全部*被删的共享组），以及因为外面还有引用、删了也腾不出来的字节。uv 识别器用它计算缓存加 `.venv` 的组合，`Recognize.refineShared` 用它把大的共享项的下限估计换成准确数字。

### 索引文件

`ScanTree.save` 把树写到 `~/Library/Application Support/SuckMyDisk/index-<volume-uuid>.bin`。文件开头是一个魔数字符串（`fastscan.c` 里的 `SNAP_MAGIC`，目前是 `SMDIDX03`）和节点大小。**只要节点布局或文件格式变了，就改 `SNAP_MAGIC`**：旧文件会被拒绝，下次启动做一次全盘扫描，而不是读错。别忘了在更新日志里写一句。

## 实时更新（`LiveIndex`）

- `DiskWatcher` 订阅数据卷的 FSEvents，从索引里存的事件 id 开始，所以 App 关着的时候发生的事件会先被重放。FSEvents 报告的是目录，不是文件。
- `LiveIndex` 把一批变化的目录变成具体工作：重读一个目录自己的条目、扫描一棵新子树、摘掉一棵被删的子树（`SM_F_DETACHED`）。C 的 patch API 直接在原地改树，并沿着父节点链修正合计。
- 一直在变的目录，最多每隔几秒重读一次。折叠起来的大子树、超过 20,000 个文件的目录、读起来慢的目录会被推迟：标成 `SM_F_STALE`，每隔几分钟在后台刷新一次。这些 stale 标记会随索引一起保存。
- 如果事件丢了、事件 id 回绕了，或者 FSEvents 数据库的 UUID 和索引里存的对不上，这一批就会要求全盘重扫（`rescanAll`）。这时候只有重扫才是对的。
- `LiveIndex.stamp` 记下的是全盘扫描*开始之前*的事件 id，所以扫描期间发生的改动会被重放，不会丢。

App 关了一段时间再打开，追上改动大约要 0.3–1 秒；持续跟踪磁盘大约占一个核的 1%。改动积累到一定程度，App 会在后台重新识别；`smd` 每次运行都会先追上改动。

## 外接磁盘

`ExternalVolumes.list()` 只靠卷属性找出 `/Volumes` 下本地、可写、可见的卷：不读任何文件夹，所以列出磁盘永远不会弹授权。网络共享、只读的磁盘映像和隐藏卷（时间机器）不算。

每块盘用同一个扫描器扫描，挂载点是唯一的根，写进它自己的 `index-<volume-uuid>.bin`。`Recognize.external` 只运行项目和渲染帧两个识别器：设置 `allowAnyPath`（哪里的项目都算，不限个人文件夹），并把盘根目录下的点文件夹划为禁区（`.Trashes`、`.Spotlight-V100`，以及从个人文件夹搬过来的点文件夹，那里面到处是 `package.json` + `node_modules`）。报告写进 `report-<volume-uuid>.json`。

外接磁盘没有 FSEvents 流：App 在它挂载时（`NSWorkspace.didMountNotification`）或启动时它已接着、点重新扫描时、以及清理之后扫描一次，其间显示保存的索引和报告。没有完全磁盘访问时只在用户要求时扫描，因为 macOS 读外接磁盘前会弹窗询问。命令行里 `smd things /Volumes/<name>` 和 `smd reclaim /Volumes/<name>` 做同样的事。

`Executor` 在条目所在的卷上测量腾出的空间（`ExternalVolumes.mountPoint`），`Guards.isDenied` 拒绝任何卷的根目录。

## 隐私

没有完全磁盘访问时，读桌面、文稿、下载、iCloud 云盘、`~/Library/Containers`、`~/Library/Group Containers` 或 `/Volumes` 会弹出授权对话框。进程没有完全磁盘访问时（检测方法是试着打开 TCC 数据库，这一步永远不会弹窗），`Privacy.rootsToSkip()` 返回这些目录，扫描器、实时更新和识别器都不会碰它们。`LiveIndexTests.privacyPromptingFoldersAreNeverOpened` 专门守着这一点。`--snapshot` 和 `--demo` 模式会设置 `Privacy.alwaysSkip`，绝不碰这些目录。

## 识别（`Recognizers`、`Insights`）

`Recognize.all` 从树生成一份 `Report`：

1. `ActivityIndex` 收集「上次在这里干活是什么时候」的信号：Claude Code 和 pi 的会话目录、Codex 会话的工作目录、fish 和 zsh 历史里的 `cd` 命令，以及 Spotlight 的上次使用日期。
2. `ProjectRecognizer` 遍历一遍树，找出项目（git 仓库或有清单文件的目录）和它们的产物。只有大到值得列出的通用目录（`build`、`dist`、`out`）才会并行跑 `git check-ignore` / `git ls-files`。最后决定哪些项预选。
3. `FrameSequenceRecognizer` 找出图片很多的目录，读几张图片的头信息，再在附近找一个帧数相同的视频（视频轨的时长 × 帧率，相差不超过 3 帧或 0.5%）。从帧往上找时，跳过别的项目（有 git 仓库或清单文件的文件夹）和装着别组帧的文件夹；帧数一样时选最新的视频。
4. 其余交给 `DevCacheRecognizer`、`ModelRecognizer`、`AppDataRecognizer` 和 `SystemRecognizer`。
5. `AppRecognizer` 根据 `Info.plist` 列出 `/Applications` 和 `~/Applications`（以及下一层）里的应用，再到 `~/Library` 里认它们的文件夹：按 bundle id、按在它后面接着的名字（`….ShipIt`、扩展的 id；归装着的应用里 id 最长的那个），在 Application Support、Caches 和 Logs 里还按和应用完全相同的名字（太通用或两个应用同名的除外）。文件夹来自树，所以受隐私保护的目录永远不会被读；小文件（偏好设置、Cookie、启动代理）来自目录列表。每个应用是一个 `.app` 类的 `Thing`，带一个「卸载」项（`yours`，由一串 `.trash` 组成的 `compound`，应用本身排第一）；缓存合计到 1 MB 时再带一个「缓存」项（`regenerable`，`.deleteAll`）。两项都带着 `app`。应用排在报告最后，这样 `smd things` 给其他东西的编号不会变。
6. `LargeFileRecognizer` 列出个人文件夹（资源库和以点开头的文件夹除外）和 `/Users/Shared` 里、上面各项都没覆盖到的大文件：每一项的路径和它的动作要删的路径都作为 `covered` 传进来。它遍历树，整棵子树比它列出的最小尺寸还小就跳过；按扩展名分组（bundle：`.app`、`.sparsebundle`、虚拟机包）；拆成几片的模型合并成它所在的文件夹（有 `model_index.json`，或权重旁边有 `config.json`）；去掉 git 跟踪的文件（每个仓库一次 `git ls-files`）；再向 Spotlight 问每个列出的文件上次打开的时间和下载来源。条目都是 `yours` / `.trash`，从不预选。
7. `BrowserRecognizer` 找 Chromium 的用户资料（来自 `Local State`）、Firefox 系的用户资料（来自 `profiles.ini`）和 Safari。它通过 `ForeignDB` 数它们数据库里的行数，以 `immutable=1` 只读打开（Chrome 运行时一直锁着这些数据库），为浏览记录、下载记录、Cookie、表单内容和会话生成 `erase` 条目，再加一个 `regenerable` 的缓存条目，去掉应用自己的缓存条目已经包含的文件夹。Safari 的浏览记录和 Cookie 是 `guide` 条目。
8. `refineShared` 对估计值只是下限的大项做精确计算。

数据模型在 `Thing.swift` 里：

- **`Thing`** 是用户认得出的一样东西：一个项目、一份缓存、一个模型仓库。它有类别、大小、上次活跃时间和一组清理项。
- **`ReclaimItem`** 是一个动作：能腾出多少（`estimate`，可能小于它占用的 `bytes`）、`Tier`、`ReclaimAction`、恢复命令、理由、警告，以及是否预选。`covers` 列出它已经包含的项（`uv cache clean` 包含 `uv cache prune`），避免重复计算或重复执行。`app` 是这一项所属的已安装应用的路径。
- **`Tier`**：`lossless`（什么都不丢，留给克隆合并用）、`regenerable`（直接删，可以重建）、`yours`（进废纸篓）、`erase`（永久清除的记录：浏览记录、Cookie）、`guide`（只给指引）。报告里按原始值存；`erase`（4）排在 `yours` 和 `guide` 之间。
- **`ReclaimAction`**：`delete`、`deleteAll`、`trash`、`command`（工具自带的清理命令）、`erase`（在别的程序的 SQLite 数据库上执行语句）、`compound`、`none`。条目上的 `records` 表示要清除多少条记录，App 显示它而不是大小。

`Planner.plan` 把用户的勾选（或预选）变成要执行的清单，并去掉已被别的项包含的项。预选永远不包括 `erase` 条目。

每个识别器都必须遵守 [CONTRIBUTING.zh-CN.md](../CONTRIBUTING.zh-CN.md#删除相关代码的安全规则) 里的规则。

## 执行（`Reclaim`）

`Executor` 一项一项地执行。每一项动手之前，对它要碰的每个路径都检查一遍：`Guards.isDenied`、路径还在且不是符号链接、git 没有跟踪里面的任何文件（拿不准就当作有）、没有正在运行的程序的命令行提到它（用 `ps` 查，同样拿不准就不删），以及 7 天规则。`force` 对所有条目解除这条规则；`chosen` 是用户亲手勾的条目，其中可再生的不受它限制，所以扫描之后又改过的预选条目照样不动。跑 uv 的命令前还会确认没有 uv 在运行，因为 uv 会等缓存的锁；同时设上 `UV_LOCK_TIMEOUT`，防止这期间正好又起了一个。受系统完整性保护（`SF_RESTRICTED`）的东西一律不碰。

带 `app` 的条目还要多查几样：应用还装着，而且没有任何东西从它里面运行（`Guards.program(inApp:in:)`，按 `/<Name>.app/Contents/` 也能认出被 macOS 挪到别处运行的副本）。用户亲手勾的，不受 7 天规则限制：打开应用就会改动它的文件夹，对应用来说要紧的是「没在运行」。识别之后消失的文件夹会从动作里去掉，而不是让整项失败（`Executor.existing`）。

`.erase` 动作要求数据库仍是普通文件、没有正在运行的程序在命令行里提到它；然后 `ForeignDB.erase` 以读写方式打开，不等待地执行 `BEGIN EXCLUSIVE`（浏览器还占着就让这一项失败，什么都不改），打开 `secure_delete`，执行各条语句（这个版本的浏览器没有的表，对应语句跳过；其他错误整体回滚），提交后再 `VACUUM`。清除的行数写进日志。

然后才动手：删除用 `removefile`，进废纸篓用 `FileManager.trashItem`，工具命令通过 `Shell` 运行。`trashItem` 移不动的 `.app`（归 root 所有，App Store 和安装器装的都是这样）交给访达，通过 `osascript` 来移，访达会像拖进废纸篓时一样要管理员密码。[卸载助手](#卸载助手privilegedhelper)打开时，App 会给执行器一个 `elevate` 闭包：先试它，不成再找访达（原因写进清理记录的详情）。删 Python 虚拟环境之前，会先记下 `pyvenv.cfg` 和一份 `pip freeze`。执行前后各量一次可用空间，所有结果都写进日志。

## 存储

`AppPaths.supportDir` 是 `~/Library/Application Support/SuckMyDisk`，设置了 `$SMD_HOME` 时用它。

| 文件 | 写入者 | 内容 |
| --- | --- | --- |
| `index-<volume-uuid>.bin` | `ScanTree.save` | 树，以及它所对应的 FSEvents 事件 id 和数据库 UUID |
| `last-report.json` | `ReportStore.save` | 最近一次的 `Report`；清理后会删掉 |
| `report-<volume-uuid>.json` | `ReportStore.save(_:to:)` | 外接磁盘最近一次的 `Report` |
| `smd.sqlite` | `Store` | `history`（每样东西每天的大小）、`volume_history`、`journal` |

## App

`AppModel` 管所有状态：加载好的树、实时更新循环、报告、勾选（刷新后保留，所有磁盘共用一份）、清理计划和清理进度。每块外接磁盘是一个 `ExternalDisk`，有自己的树、报告和扫描进度；`page` 记录现在显示的是启动磁盘的某个分区还是某块外接磁盘，`cleanDisk` 记录「清理」要处理哪块盘。它从 `AppDelegate.applicationDidFinishLaunching` 启动，所以即使 App 启动时只有菜单栏图标、没有打开主窗口，也照常工作；退出时保存索引。

`--snapshot <dir>` 把每个页面渲染成 PNG 然后退出。`scripts/snapshots.sh` 通过 LaunchServices 用这个模式启动 App（只有这样 Liquid Glass 才能正常渲染），再在有屏幕录制权限的终端里截取窗口。

清理列表是 `CategoryView`，每个分区一个（`.id(section)`，所以每个列表都会展开自己的前几组）。「应用」有几处不同：侧边栏、卡片和标题显示应用占的空间，而不是「可以腾出」（把所有应用都卸载不算一个计划）；概览的「等你决定」、时间线和容量条都不算它（和应用数据、应用程序重叠）；每一行显示应用图标；「卸载」项下面用树里的大小列出它的数据文件夹（`AppDataList`）。清理确认窗口把卸载单独分成一组。

`--demo` 用 `Demo.swift` 里的虚构数据代替磁盘：一份报告；一份用 `ScanTree.synthetic` 按文件夹大小清单搭出来的索引（先用 `sm_tree_create` 建一棵空树，再通过实时更新的补丁接口填进去，全程不碰磁盘）；两周的时间线；磁盘容量数字；虚构的应用（图标用首字母方块，不会显示任何真实应用的图标）；以及一块虚构的外接磁盘（「Studio SSD」）。这时 `AppModel` 会跳过重新扫描和保存，「清理」只是把条目从列表里拿掉，演示数据永远不会交给执行器。`scripts/doc-screenshots.sh` 用演示模式运行 `snapshots.sh`，生成 `docs/images` 里的截图。

## 卸载助手（`Privileged`、`Helper`）

归 root 所有的应用只有 root 移得动。为了不用每次都过访达的密码框，可以一次性打开一个助手：它是放在 App 包里的 launchd 守护进程（`Contents/MacOS/com.kadaliao.SuckMyDisk.helper`，任务描述在 `Contents/Library/LaunchDaemons`），由 `App/Helper.swift` 用 `SMAppService.daemon` 注册，再由用户在系统设置里允许。包外面不放任何东西，所以更新 App 的同时也就更新了助手。

它是 root，所以做得很小，而且不相信收到的任何东西：

- **谁能调用。** 监听端设了 `setConnectionCodeSigningRequirement`：标识符 `com.kadaliao.SuckMyDisk`、Apple 根证书，以及给助手自己签名的那个团队（从它自己的签名里读，所以 fork 出来的构建信任的是 fork 的 App）。没有团队签名的助手拒绝运行。App 这一端也设了对应的要求。用户取自连接本身（`effectiveUserIdentifier`），而且必须在 `admin` 组里。
- **它做什么。** 只有一条消息 `trashApp(path)`，由 `AppMover` 处理：路径必须是 `/Applications/<名字>.app` 或往下一层（不能是「实用工具」，不能在别的包里面，不能有 `.`、`..` 或空的部分）；它必须是一个真的文件夹，有 bundle id，不受 SIP 保护，不是 SuckMyDisk，也没有进程从里面运行（用 `proc_pidpath` 查；不启动子进程，所以不会以 root 身份去 PATH 里找程序）。废纸篓必须是调用者自己的真文件夹，并且在同一个卷上。
- **移动** 只是一次 `renameatx_np`，带 `RENAME_EXCL | RENAME_NOFOLLOW_ANY`：从不覆盖已有的东西，两边路径上只要有一段是符号链接就失败，所以检查之后再偷换也改不了去向。
- **生命周期。** launchd 按需启动（`MachServices`），空闲 30 秒自己退出。`hello` 返回 `Privileged.version`；更新之前留下来的旧助手会被要求 `quit`，由新的程序来回答。

`smd` 不用助手（它的签名不是 App 的），演示、截图和非正式构建从不注册它。

## 自动更新（`Update`、`Updater`）

`Updates.latest` 从 GitHub API 读 `releases/latest`（它会跳过草稿和 pre-release），只有标签是纯版本号（`v0.5.1`）、附件里有 `SuckMyDisk-<version>.zip` 和 `SHA256SUMS` 时才采用。`release.sh` 正好产出这两样，所以发布一个 release 就够了。安装分四步：

1. `download` 先取 `SHA256SUMS`，再把 zip 下载到 `~/Library/Caches/com.kadaliao.SuckMyDisk/Updates`（那里已有完好的一份就直接复用），哈希对不上就丢掉。
2. `unpack` 用 `ditto` 解压到和已安装 App 同一个卷上的 `itemReplacementDirectory`，再由 `verify` 检查 App：用 `SecStaticCodeCheckValidity`（所有架构、嵌套代码、严格模式）对照 `Updates.requirement`（bundle id、Developer ID Application、团队 `HMDAVG9B8J`、`notarized`），然后 `Info.plist` 里的版本号必须和 release 一致。只接受比正在运行的版本更新的版本，所以旧的正版 release 没法被拿来重放。
3. `swap` 用 `renamex_np(…, RENAME_SWAP)` 让两个 bundle 互换位置，那个路径上每一刻都是完整的 App；然后删掉旧的。
4. `relaunch` 用 posix_spawn 在新会话里起一个 `/bin/sh`（否则 launchd 会把它和 App 的任务一起杀掉），等 App 的 PID 退出后执行 `open -a`。原来窗口关着时带上 `--hidden`，让窗口保持关闭（`defaultLaunchBehavior(.suppressed)`）。

两个版本之间指定要求（designated requirement）不变，所以 TCC 里的完全磁盘访问授权保留。

App 里的 `Updater` 决定什么时候做。上次检查已经过了一天的话，启动 30 秒后检查，之后每分钟看一次。网络出问题一小时后重试；某个版本自己的检查或安装没通过，后台就不再碰它，直到出了更新的版本，侧边栏卡片会写明原因。下载好的更新马上检查，坏的不会留着等安装。开着自动安装时，等 App 不在前台、没被隐藏、没有打开的窗口、也没有在载入、扫描、识别或清理时安装，装完这些条件仍然成立才重新打开；否则由 `applicationWillTerminate` 在退出时安装。用户自己点的重新打开，会等正在进行的扫描或清理结束。App 没法替换自己时（App Translocation、只读卷即 DMG、没有写权限），`Updates.blocker` 给出原因。不是用 Developer ID 签名的构建（Xcode）、`--demo` 和 `--snapshot` 都不检查更新。

## 多语言

App 和命令行里所有给用户看的文字，都通过 `Fmt.swift` 里的 `L("中文", "English")` 输出。首选语言以 `zh` 开头时用中文；`SMD_LANG` 可以覆盖。项目不用字符串目录（string catalog）：两种语言就并排写在代码里，改一种时不会忘了另一种。

大小用十进制单位，和访达一致（`Fmt.bytes`）。

## 测试

在 `Packages/DiskCore` 里运行 `swift test`，会对临时目录里搭的测试数据跑 Swift Testing 测试套件：

- `ScannerTests`：克隆和硬链接的计数、折叠和标记位、快照的保存与读回、合成树、firmlinks。
- `AccountingTests`：同时释放 uv 缓存和 `.venv`。
- `RecognizerTests`：项目产物和恢复命令、活跃项目不预选、外接磁盘上的项目（不含盘上的点文件夹）、帧只和自己的视频配对、npx 的包、渲染帧序列和相机连拍的区分。
- `AppTests`：列出哪些应用、哪个文件夹归哪个应用（后缀、带团队 ID 的群组容器、厂商文件夹和通用名字不算）、Homebrew 和系统组件的警告、正在运行的应用不动（被挪到别处运行的副本也算）、亲手勾的应用条目和 7 天规则、应用已经不在时如实报告、公共文件夹受保护。
- `PrivilegedTests`：以普通用户身份在临时文件夹里检验助手的规则：哪些路径算「应用程序」文件夹里的应用、该拒绝的都拒绝（非管理员、正在运行的应用、SuckMyDisk 自己、不属于调用者的废纸篓）、两边都不跟随符号链接、不覆盖废纸篓里已有的东西，以及执行器只为自己移不动的应用去找助手。
- `LargeFileTests`：只列别处没列出的（点文件夹、折叠的依赖、git 跟踪的文件、别的条目和保险库分块都不算）、拆成几片的模型按一个文件夹算、安装包认出对应的应用。
- `BrowserTests`：Chromium 用户资料逐项清除（下载记录、同步记录、银行卡和搜索引擎保留）、被占着的数据库不动、正在运行的浏览器不动、Firefox 清浏览记录保留书签、报告里的 erase 等级。
- `SafetyTests`：受保护位置、被包含的项、执行器拒绝受保护路径和 git 跟踪的路径、正在运行的程序在用的文件、7 天规则和什么情况下不受它限制、uv 不再干等别的 uv 进程、Node 脚本在 App 的精简 PATH 下也能找到 `node`。
- `LiveIndexTests`：打过补丁的树和重新扫描的结果一致、保存后的树能继续增长、大目录排队等待、会弹授权的目录从不被打开、FSEvents 驱动更新。
